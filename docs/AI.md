# 日历 AI 的行为约定

目标：在需求日历内，通过对话完成需求管理。DeepSeek Harness 负责会话和工具调用，日历负责权限、校验、持久化和界面刷新。

## 用户体验

- 工具栏提供「日历助手」，打开可收起的对话侧栏；保留月历与需求详情。
- 在助手设置中填写 DeepSeek API Key、服务地址与模型，保存个人工作习惯，分别授权读取、创建、修改、删除。
- 对话使用当前日期、时区、正在看的月份和用户主动填写的工作习惯。需求内容按工具调用读取。
- 显示执行结果，能从结果打开对应需求。支持停止、新对话、恢复历史。
- API Key 不进入前端本地存储、聊天记录、需求备份或模型提示词。Mac 使用钥匙串，Windows 使用系统凭据加密。
- 对话、偏好和工具操作记录保存在本机；调用模型时，消息和授权读取的日历信息发送到用户配置的服务。

## 工具边界

使用官方 `@deepseek-ai/dsh-sdk-client`，固定 `0.2.1-rc.3`，运行独立的 `sdk-minimal` profile，并禁用文件、终端与工作目录工具；专用插件仅暴露日历工具。

所有写操作进入现有 `CalendarApp.executeCommand`，沿用字段校验、草稿保护、revision 检查、原子保存和备份；禁止直接改写 `calendar.json`。权限每次调用都重新检查，撤销立即生效。

## 本机 API

设置内启用 API 后显示本机地址和访问令牌，仅监听 `127.0.0.1`，请求必须携带 `Authorization: Bearer TOKEN`。默认关闭；与内置助手共用操作权限。

调用时保持应用运行。重启通常沿用原端口；端口被占用时会选择空闲端口，设置中显示实际地址，也可从数据目录下的 `assistant/endpoint.json` 读取。操作权限约束内置助手和本机 API；原有 CLI 仍按当前本机用户权限执行。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/v1/status` | 当前 revision 与数量 |
| GET | `/v1/schema` | 日历指令字段规则 |
| GET | `/v1/requirements` | 查询需求，支持 from/to/query |
| POST | `/v1/requirements` | 创建需求 |
| GET | `/v1/requirements/:id` | 查看详情 |
| PATCH | `/v1/requirements/:id` | 修改需求 |
| DELETE | `/v1/requirements/:id` | 删除需求 |
| POST | `/v1/requirements/:id/shift` | 整体平移 |

写操作需要 `If-Match: REVISION`，创建推荐提供稳定的 `id`。冲突返回 409，权限不足返回 403，校验失败返回 422。不要在连接中断后盲目重试写入，先查询对应 ID。

## 验证清单

- 官方 Harness 启动、调用真实日历工具、读取结果并生成回复；模型协议使用本机测试服务器验证，不依赖付费 API Key。
- 创建、修改、删除、平移立即保存且刷新；重启恢复。
- 未授权动作拒绝，撤权立即生效，旧 revision 和未保存草稿不会被覆盖。
- API 未启用、错误令牌、浏览器跨站访问、无 If-Match、无效输入拒绝。
- 设置、工作习惯、会话历史持久化；API Key 不出现在 JSON、日志或前端状态。
- UI：空状态、设置、发送、执行结果、错误、停止、历史、新对话；1160×780 与最小窗口下无裁切。
